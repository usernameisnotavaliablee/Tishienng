## 二、电商拉起判定 ★

**结论：主程序确实主动拉起淘宝/京东，但触发条件是「首页轮播 Banner 的用户点击」，是校园商城/CPS 导购功能，不是后台静默或广告回调自启。**

### 2.1 调用链（首页 Banner 点击 → 唤起电商）
- 首页 Banner 点击回调：`com/bxkj/student/v2/ui/main/HomeFragment.java`
  - `bannerType=="4"` → 拼 `taobao://item.taobao.com/item.htm?id=` 直接 startActivity 拉起淘宝，失败回退 `https://item.taobao.com/item.htm?id=`（浏览器）：HomeFragment.java:146-190
  - `bannerType=="3"` → 拼 `openApp.jdMobile://virtual?params={"category":"jump","des":"productDetail","skuId":"…"}` 拉起京东，失败回退 `linkUrl`：HomeFragment.java:199-231
  - `bannerType=="2"` → 小程序(appletId/appletPath)：HomeFragment.java:240-257
- 商品 id 来自服务端 Banner 数据字段 `jdPath`/`linkUrl`（HomeFragment.java:153、222）。
- Banner 数据源为 `app/getTopAd`（v2/retrofit/b.java:174-177）。

### 2.2 与广告 SDK 的区分
- 广点通/穿山甲/BeiZi 等广告 SDK（com.qq.e、com.bytedance、com.beizi）自带 tbopen/taobao 能力，属「广告 SDK 回调」。
- 本处 `HomeFragment` 是**主业务自身代码**、用户点击触发，与广告 SDK 无关 —— 这是主程序主动拉起电商的**实锤**。
- 另外 App 启动（同意隐私协议后）初始化 `com.acse.ottn.activity.AcseHelpManager`（"省钱助手"导购 SDK）：App.java:933-948。该 SDK（cap_8）自带无障碍服务 `ShopHelperService`、`HomeKeyReceiver`、设备管理器，是第三方 CPS 导流/拉活组件，属「SDK 自带」，非主程序自写逻辑。

### 2.3 判定
- **主动拉电商：是**（商城导购 CPS 功能，HomeFragment 直接拼 taobao://、jdMobile://）。
- **触发条件：用户点击首页商城 Banner**（bannerType=3/4），非后台定时/通知点击/广告回调。
- 无发现无提示后台拉起电商的代码路径。

## 三、设备指纹「采集 → 组装 → 上报」链路 ★

### 3.1 采集层
1. `gank_device_id`（a0.java:16-86）：
   - 优先 `Settings.Secure.ANDROID_ID` → `UUID.nameUUIDFromBytes(...)`；
   - 若 android_id 为已知模拟器值 `9774d56d682e549c` 或空 → **`TelephonyManager.getDeviceId()`（IMEI）** 再 UUID 化（a0.java:54-67）；
   - 再兜底 `UUID.randomUUID()`。
2. 百度联天设备指纹 SDK：`com.baidu.liantian.ac.LH.init / LH.getId(context,"1")`（f.java:46-48），取其 second 值转大写。
3. 合成为 `uniqueCode = MD5( gank_device_id + 联天id )`（f.java:169-196）。

### 3.2 组装层（基础参数 b0.a）
`b0/a.java:14-59` 每次启动静态组装一份 LinkedHashMap：
`appType="Android"`、`versionCode`、`versionName`、`signatureMD5`(APK 签名)、`brand`、`model`、`system`、`version`、**`uniqueCode`**(设备指纹)。

### 3.3 上报层（两条通道）
**通道 A —— 全量请求头（最广）：** `y/c.java`（RequestInterceptor）给每个 HTTP 请求加头：
- `uniqueCode: <设备指纹>`：y/c.java:214-219
- `timestamp: <毫秒时间戳>`：y/c.java:229-239
- `appId = Transform.u(context, appId, token, timestamp)`：y/c.java:244
- `appSecret = Transform.v(context, token, timestamp)`：y/c.java:247
- `sign = Transform.r(context, token, {所有参数 + appId + appSecret + timestamp})`：y/c.java:283-287 / 349-350 / 385-386 / 424-425
- 另带 `school`(学校代码)、`Cookie: host=<school>`、`Authorization: Bearer <token>`（非白名单域）：y/c.java:171-218

**通道 B —— 敏感业务体加密上传（人脸/运动）：**
- 人脸：`face/c.java` 组装 paramMap = b0.a 基础参数 + identify/type/runType/coordinates/timeStamp/exception + **environment{deviceId, safe, oppo}**（face/c.java:207-285），JSON 化后经 `b0.b.b(context, token, timestamp, json)`（= `Transform.s`）得到 `{key, param}`，再 multipart 上传 `key`、`param`、`file` 到 `app/faceDetect`（face/c.java:336-377、b.java:341-343）。
- `environment`(deviceId/safe/oppo) 由反作弊模块 `safe/e.java`（EnvironmentCheck）生成（含 sign/root/emu 检测结果）写入 Room 表 l0/a。
- 运动记录：`sports/g.java`(commitV3_2/passPointCameraV2)、`SportsHomeVM`(getSportSetV2)、`SportsHomeRepository`(getSportsResultV2) 同样走 `b0.b.b → Transform.s`，上报 `app/addExerciseRecord`、`app/exerciseSettingV2` 等（sports/g.java:9、136；b.java:222-228）。

### 3.4 上报接口（Retrofit @POST/@GET 路径，b.java）
`app/login`、`app/autoLogin`、`app/thirdLogin`、`app/faceDetect`、`app/faceCollect`、`app/faceCheck`、`app/checkFaceResult`、`app/addExerciseRecord`、`app/exerciseSettingV2`、`app/getAuth`、`app/update`、`app/getPgyerAppVersion`、`app/bugReport`、`app/feedbackExerciseRecord`、`app/getUserInfo` 等（b.java:169-398；运动类 run/app/a.java）。

### 3.5 服务器域名是「native 解密」而非明文常量
- 基础 URL：`data/b.java` M() → `Transform.k(context, "05dbfd8c595b3687f8351745f27c449b")` 解密，再读 SharedPreferences `schoolUrl`（默认=解密值）：data/b.java:385-422。
- 拦截器白名单/排除域同样用 `Transform.k` 解密若干 32 位 hex 串（如 `7e9c6f977d2da2dbe67cd1005eaaf6e1`、`e5c6b9630a11efdfa31a4cfa4b227688`…）：y/c.java:122-166。
- 因此 **Java 层搜不到明文域名**；a.tsnkj.com / h.tsnkj.com / m.boxkj.com 等域名是经 libtsnsecret.so 解密得到。

**链路小结：** android_id(兜底IMEI)+联天指纹 → MD5 → `uniqueCode`，随每个请求头(通道A)及人脸/运动加密体(通道B)经 Retrofit 上传到（native 解密的）schoolUrl 后端。

## 四、native 鉴权（auth / generateAuthInfo）业务调用链 ★

### 4.1 native 声明与加载
- `com/google/android/datatransport/Transform.java` 静态块 `System.loadLibrary("tsnsecret")`：Transform.java:15-17。
- native 方法（已由前几轮 unidbg 还原的 aes_decrypt/auth/generateAuthInfo 在此以单字母命名）：
  `s(ctx, token, timestamp, data)→String[]`、`t(ctx, enc, key)→String`、`u(ctx, appId, token, timestamp)→String`、`v(ctx, token, timestamp)→String`、`r(ctx, token, map)→String`、`k(ctx, enc)→String` 等：Transform.java:26-67。
- Kotlin 包装 `b0/b.java`：`a()`→t、`b()`→s、`d()`→u、`e()`→v、`h()`→r、`l()`→k、`c()`→d、`f()/g()/j()/k()/m()/n()/o()`→a/g/i/x/e/f/h：b0/b.java:24-198。

### 4.2 触发点（哪些业务请求前先鉴权/签名）
1. **每一个 API 请求**（登录、打卡、人脸、商城、课程…全部）在 `y/c.java` 拦截器里先调 native 生成 `appId/appSecret/sign`（见 §3.3 通道 A）。
2. **人脸核验** `app/faceDetect`：face/c.java:342-377 先 `Transform.s` 加密业务体再上传。
3. **跑步打卡** `app/addExerciseRecord` / `app/exerciseSettingV2`：sports/g.java、SportsHomeVM、SportsHomeRepository 先 `Transform.s`。
4. 点名拍照、运动过程照 `passPointCameraV2`：sports/g.java:136。
5. **基础 URL/白名单域解密**：`Transform.k`（data/b.java:392、y/c.java:122-166）。

### 4.3 签名串包含的参数（Map key 清单）
- 基础参数（b0/a.java:20-58）：`appType`、`versionCode`、`versionName`、`signatureMD5`、`brand`、`model`、`system`、`version`、`uniqueCode`。
- 拦截器 sign 的 map（y/c.java:257-289）：**请求自带的所有 query/form/multipart/json 参数 + `appId` + `appSecret` + `timestamp`**，再交给 `Transform.r` 出 `sign`。
- 业务体加密前 map（face/c.java:207-229 例）：基础参数 + `identify`、`type`、`runType`、`coordinates`、`timeStamp`、`exception` + `environment{deviceId,safe,oppo}`。

> 映射（推断，依据调用点形参与前轮 unidbg 结论）：`Transform.s ≈ generateAuthInfo`（返回 key+param）、`Transform.t ≈ aes_decrypt`、`Transform.u/v ≈ auth`、`Transform.r ≈ 签名`、`Transform.k ≈ 固定密钥解密(URL)`。

## 六、SecretActivity 用途 ★

`com/bxkj/student/SecretActivity.java`（全貌已读，162 行）：

1. **门禁**：内置 8 个 UUID 白名单（SecretActivity.java:31-53），用 `f.d(context)`（= MD5(gank_device_id + 联天id)，32位hex）做 `contains` 判断；不在白名单 → toast「你想干什么？」+ finish（SecretActivity.java:55-63）。
   - ⚠️ **格式存疑**：白名单是 UUID（8-4-4-4-12），而 `f.d()` 返回 MD5(32hex)，二者格式不匹配，按反编译逻辑该门禁大概率永不通过（即后门在当前版本可能已失效/死代码）——此点以"事实+推断"标注。
2. **通过门禁后**：
   - 接受 Intent extras `school_name / school_url / school_id / openId` → 改写 `LoginUser` 的学校名、服务器地址、学校 id、appId，并 `Http.changeBaseUrl(school_url)`（SecretActivity.java:65-100）；
   - 若还有 `userId / name / userNum` → 直接 `setLogin(true)` + 伪造任意用户登录态，跳 MainActivity；否则跳 LoginActivity（SecretActivity.java:102-144）。
3. **manifest**：`exported="true"`、**无权限保护**（manifest:367）。
4. **攻击面评估**：这是一个**导出、无鉴权的"切服 + 任意用户免密登录"后门**（内测/演示用）。任何第三方 App 只需 `startActivity(new Intent(ComponentName("com.bxkj.student","com.bxkj.student.SecretActivity")).putExtra(...))` 即可尝试触发；唯一的防护是设备 UUID 白名单，且该白名单与比对值(MD5)格式不一致。属高危攻击面：可诱导/劫持 App 指向任意后端并伪造登录身份。

## 八、「事实 / 推断」分界总结

### 事实（反编译代码 + manifest 直接可见）
1. 首页商城 Banner 点击主动拉起淘宝(taobao://)、京东(openApp.jdMobile://) —— HomeFragment.java:146-231。
2. `System.loadLibrary("tsnsecret")` 位于伪装的 `com.google.android.datatransport.Transform`（cap_8），native 方法单字母化 —— Transform.java:16、26-67。
3. 每个 HTTP 请求都带 `uniqueCode`(设备指纹)、`sign`、`appId`、`appSecret`、`timestamp` 头 —— y/c.java。
4. 设备指纹 = MD5(android_id→UUID [兜底IMEI] + 百度联天LH.getId) —— a0.java、f.java。
5. 服务器域名在 Java 层是密文，经 native `Transform.k` 解密 —— data/b.java:392、y/c.java:122-166。
6. `SecretActivity` exported=true、无权限，白名单 UUID 8 个，门禁用 `f.d()`(MD5) 比对，通过后可改服务器地址+任意用户免密登录 —— SecretActivity.java、manifest:367。
7. 主业务无 BOOT_COMPLETED/电源类自启动广播；JPush 显式 enableAutoWakeup(false) —— App.java:814；manifest 中 BOOT 仅 androidx.work 且 enabled=false。
8. `usesCleartextTraffic="true"` + networkSecurityConfig，明文 HTTP 被允许 —— manifest:174。
9. 明文 http:// 出现在分享/图片资源/学校 H5/更新下载/商城 H5，未发现人脸/账号走明文 API —— 见 §七 与 HomeFragment/MyFragment/GoodsDetailActivity 等。

### 推断（需动态验证）
