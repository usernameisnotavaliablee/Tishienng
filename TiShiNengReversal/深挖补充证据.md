### 1.3 拉活广播 action（receiver 监听的系统事件）

`com.acse.ottn` 的 `HomeKeyReceiver`（监听 Home 键）+ 整套电量/开机/时间广播触发保活，已确认的 action（manifest 全量）：
```
BOOT_COMPLETED, ACTION_POWER_CONNECTED, ACTION_POWER_DISCONNECTED,
BATTERY_LOW, BATTERY_OKAY, TIME_SET, TIMEZONE_CHANGED,
DEVICE_STORAGE_LOW, DEVICE_STORAGE_OK, CONNECTIVITY_CHANGE
```
→ 几乎"任何系统状态变化"都能把它从后台拉起来。`DEVICE_STORAGE_LOW/OK`、`TIMEZONE_CHANGED` 是 HANDOFF 未列出的新增项。

> **⚠️ 第7轮修正（2026-08-14 脱壳后深挖，修正①）**：上表把 `BOOT_COMPLETED` / `ACTION_POWER_*` / `BATTERY_*` / `TIME_SET` / `TIMEZONE_CHANGED` / `DEVICE_STORAGE_*` / `CONNECTIVITY_CHANGE` 归给「com.acse.ottn 的 HomeKeyReceiver」**有误**。经核对 `manifest_decoded.xml:1171-1210`，这些广播 action **全部属于 androidx.work（WorkManager 的 `ConstraintProxy*` / `RescheduleReceiver`）**，与 acse 无关。acse 自己的 `HomeKeyReceiver` 在 manifest **无 `<intent-filter>`**（`manifest_decoded.xml:1255-1256`），且 Java 层**无 registerReceiver**（`HomeKeyReceiver.java:149` 仅空 `onReceive`，半成品空壳）。acse 真正生效的 Home/熄屏监听是 `m1.java` **动态注册** `CLOSE_SYSTEM_DIALOGS` + `SCREEN_OFF` → `finishAndRemoveTask()` 抹掉自家导流 Activity（`m1.java:409-427/75-77/122-124`）。详见《体适能_脱壳取证_无障碍与保活机制.md》§2.1/§2.9。

## 2. ★★★ 新实锤：广点通(GDT)广告插件内置「淘宝/京东拉起」能力

HANDOFF §5.2 留了一个 open question：「淘宝拉活静态扫不到，需脱壳」。**本轮在 `assets/gdt_plugin/gdtadv2.jar` 里直接静态扫到了电商拉起代码**——它是明文 dex（运行时动态加载，不受 360 加固保护）。

提取路径：`tsn/adjars/gdt/classes.dex`（从 jar 解出）。其中明文字符串：
```
taobao://m.taobao.com
tbopen://m.taobao.com          ← 淘宝客户端 deeplink scheme
com.taobao.taobao              ← 唤起淘宝包名
com.jingdong.app.mall          ← 唤起京东包名
market://details?id=%s         ← 跳应用市场下载
openApp / getScheme / addDataScheme / wx_scheme_dstlink
```
→ **广点通广告 SDK（腾讯系）内置了"点击广告 → 唤起淘宝/京东 App 或跳应用市场"的电商导流能力**。这是它作为信息流/电商广告 SDK 的标准变现路径。

**精确定性（不夸大）**：
- 这是 **GDT 广告 SDK 自带的能力**，随广告内容触发，**不等于"体适能主程序主动半夜拉淘宝"**。后者仍需脱壳看主 app（`com.bxkj.student`）是否主动调用——见脱壳手册 §5.5。
- 但它**修正了 HANDOFF 的结论**：淘宝/京东拉起代码**确实在包内静态存在**，只是藏在动态加载的广告 jar 里，而非主 dex。所以"这个校园 app 具备唤起淘宝/京东的客观能力"是**静态可证的事实**。

GDT 插件还自带两个 native 风控/加固 SO（解 jar 可见）：
- `lib/*/libyaqpro.so`、`libyaqbasic.so` —— 顽石(Payegis/爱加密系) 应用加固
- `lib/*/libturingau.so` —— 腾讯 Turing 设备风控/反作弊
说明这套广告变现链路本身防逆向、带设备指纹采集。

## 3. 灰产组件 com.acse.ottn 的资源级定罪（已解 res，补全）

`res/uk.xml`（`ShopHelperService` 的无障碍配置，已用 `axml_decode.py` 解出）实测全文：
```xml
<accessibility-service
    accessibilityEventTypes="0xffffffff"      <!-- 监听全部事件类型 -->
    accessibilityFeedbackType="0xffffffff"
    notificationTimeout="100"                 <!-- ~实时轮询 -->
    accessibilityFlags="0x5a"
    canRetrieveWindowContent="true"           <!-- 读取任意其它 App 窗口内容 -->
    canRequestTouchExplorationMode="true"
    canRequestEnhancedWebAccessibility="true" <!-- 向网页注入 -->
    canPerformGestures="true"                 <!-- 模拟手势/自动点击 -->
    canTakeScreenshot="true"                  <!-- 截屏 -->
    isAccessibilityTool="true" />
```
`res/cq.xml`（`MyDeviceAdminReceiver` 策略）实测：
```xml
<device-admin><uses-policies><force-lock/></uses-policies></device-admin>
```
→ 一个名为"购物助手(ShopHelper)"的无障碍服务，要齐了"读全机窗口 + 模拟点击 + 截屏 + 注入网页 + 100ms 实时轮询"全套能力，配合 `force-lock` 设备管理员防卸载。**这套能力组合远超校园打卡业务所需，是自动化导流/拉活/模拟点击灰产的标准配置。

> **⚠️ 第7轮修正（资源级定罪补充）**：本节此前只解出 `res/uk.xml` 与 `res/cq.xml` 两个资源文件。脱壳后进一步坐实落地链：`force-lock` 设备管理员策略配合 `b4.java` 的 `TYPE_ACCESSIBILITY_OVERLAY` 锁屏悬浮层（`b4.java:128-168`）与 `l2.java:45-51` 的 `performGlobalAction(8)=GLOBAL_ACTION_LOCK_SCREEN`（SDK≥28）锁屏触发点落地；无障碍能力（读全机窗口/模拟点击/截屏/注入网页）由 `d.java`（5450 行）自动化引擎、`b.java` 点击执行器、`a3.java` 截屏上报链承接。另：acse 的 `HomeKeyReceiver` 实为**空壳**（manifest 无 intent-filter、Java 无 registerReceiver），真实 Home/熄屏监听在 `m1.java` 动态注册（见 §1.3 修正注记）。详见《体适能_脱壳取证_无障碍与保活机制.md》。

### 5.2 工程/合规问题汇总（部分为 HANDOFF 已提，此处补新）

- `targetSdkVersion=30`（2020 标准），2026 年仍未升级 → 规避新版 Android 的运行时权限/后台限制/隐私沙箱要求（**这正是它能用上越界保活手段的前提**）。

## 6. 新证据一句话总结（相对 HANDOFF 的增量）

1. **电商拉起代码静态坐实**：`gdt_plugin/gdtadv2.jar`（明文，运行时加载）内含 `tbopen://`/`taobao://`/`com.taobao.taobao`/`com.jingdong.app.mall`/`market://` + `openApp` —— 修正了 HANDOFF"淘宝拉活静态扫不到"的结论：能力在包内客观存在（属 GDT 广告 SDK）。
2. **第二套环境检测**：`libumeng-spy.so` 内置模拟器/Root/Xposed/Substrate/QEMU 全套特征库（独立于 `com.snail.antifake`）。
3. **倍孜广告设备指纹手段**：`libdevInfo.so` 的 `getBootMark`/`getUpdateMark` + `boot_id` 反卸载追踪。
4. **GDT 自带 12 厂商 OAID 采集器** + **荣耀 OAID**，跨 app 广告追踪面更大。
5. **新增回传域名** `infrasec-openapi-cn.heytapmobi.com`（OPPO 安全），**热更通道** `pgyer.com` 编进核心库。
6. **GDT 广告链路自带 native 加固/风控**：`libyaqpro`(Payegis)、`libturingau`(腾讯 Turing)。
7. **全量组件清单**：23 provider（4 广告+抖音直播+穿山甲下载器各自独立）、10 个全 exported 的 `com.acse.ottn` service、导出无保护的 `SecretActivity`。
8. **签名**：自签名证书 2017→2042（25 年），主体仅"boxinkeji/xian/shanxi"。
9. **res 级定罪**：`res/uk.xml` 无障碍全能力 + `res/cq.xml` force-lock 全文已解出（§3）。

> 仍需动态脱壳才能升级为"主程序主动行为"实锤的部分：主 app（`com.bxkj.student.*`）是否**主动**调用 GDT 的电商拉起 / `com.acse.ottn` 导流目标 URL / `libdevInfo` 采集字段的实际上报接口。操作手册见 `脱壳与解密分析.md` §5。
