# 第 8 轮：静态取证修订版计划（两版评价合并收敛）

> 状态：修订版全文（2026-08-15）。依据：对原 3 阶段计划的两次独立评价（我的初评 + 第二份外部评价）逐条实测后合并，共 10 条修改。
> 目标：com.acse.ottn 7 个 `native onCreate` Activity 的入口映射（interface11 装载链）、43 个 SO 的逐项排除表、7 个第三方 dex（cap_1/2/3/5/6/7/9）批量 jadx 基线、cap_0（壳/StubApp）管道收口、URL 链复核。
> 预期结论：7/7（或接近）Activity 的 native 实现属**静态不可判定**（壳在运行时生成二级模块，磁盘上无 RegisterNatives 可证实现）——这是计划认可的合法交付，不是失败。

---

## 0. 合规与资源边界（全程有效）

- 不启动 app、不建 AVD、不访问生产网络、不连 C2、不重打包、不分发。纯静态只读分析 + 本地脚本。
- "静态不可判定"是可接受结论，必须如实标注，禁止臆测填充。
- 单线程：cap 顺序执行 + `jadx -j 1`。
- 工具：`dsh-vm/tools/bin/jadx`（1.5.1），命令模板（自工作区根目录）：
  `JADX_OPTS="-Duser.home=$PWD/dsh-vm/tools/jadx-home" dsh-vm/tools/bin/jadx -m fallback -j 1 -d <outdir> <dex>`
- 不重跑 cap_4/cap_8（既有产物有效）；不重写既有报告结论，新证据以增量段落追加。

## 3. Phase 2（先行）：第三方 dex 批量 jadx（第 8、9 条）

> 先行理由：完全独立于 native 链，工具无关，必能产出。cap 顺序：1 → 2 → 3 → 5 → 6 → 7 → 9，单线程 `-j 1`。

### 3.1 先做 smoke 对比（cap_1 双模式）
- 同输入 cap_1，分别 `-m fallback` 与 `-m simple` 各跑一次到临时目录。
- 对比：类数、生成 .java 数、退出码、耗时。选优模式作为后续 6 个 cap 的统一模式（预期 fallback 胜出，记录实测）。
- smoke 结果写入 `dsh-vm/logs/round8_smoke_cap1.md`。

### 3.2 批量执行
- 每个 cap 独立输出目录：`dsh-vm/dumps/jadx_out/cap_N/`，独立日志 `dsh-vm/logs/jadx_cap_N.log`。
- 日志固定字段（第 9 条）：输入文件 SHA-256、jadx 版本、完整命令、起止时间、退出码、产出 .java 数/类数。
- 命令：`... jadx -m <选定模式> -j 1 -d dsh-vm/dumps/jadx_out/cap_N dsh-vm/dumps/dexcap/dexcap/cap_N_sz*.dex 2>&1 | tee dsh-vm/logs/jadx_cap_N.log`。

### 3.3 汇总 → `dsh-vm/logs/round8_jadx_summary.md`
- 固定字段：cap、SHA-256、类数、.java 数、退出码、耗时、模式。
- SDK 归属：保守归因（按包名前缀与既有报告交叉），无法确定的写 `unknown`，不臆测。

## 4. Phase 1（与 preflight 并行）：native 入口映射（第 3、4、5、6 条）

### 4.1 cap_0 管道收口（第 3 条）
- `python3 probe_dex_structure.py dsh-vm/dumps/dexcap/dexcap/cap_0_sz45352584.dex`（确认 4 类/壳特征）。
- 修 `decode_jiagu_meta.py` 硬编码路径 → 指向本机 cap_0/classes.dex，跑元数据解码。
- 一次廉价 jadx（4 类，秒级）到 `dsh-vm/dumps/jadx_out/cap_0/`。
- 产出预期 = StubApp 声明级（`interface11` 为 native，只有声明）；**不承诺"恢复实现"**，默认结论：静态不可判定。

### 4.2 interface11 ID 出处落报告（第 4 条）
- 出处 = cap_8 jadx 输出 `static{}` 块的寄存器赋值行（如 `ExcessActivity.java:7  r0 = 9579(0x256b,…)` + `:8  com.stub.StubApp.interface11(r0)`），逐 Activity 记录 `文件:行`。
- 语义注明：ID 是壳装载器索引，与"业务逻辑"无直接对应。

### 4.3 完整 SO 排除表（第 5 条）
- 43 个 SO（arm64-v8a 与 armeabi-v7a 各 43）逐项给排除证据，字段：SO 名、大小、排除结论（第三方 SDK 名/壳自身/无关）、证据（strings/既有报告/unidbg 结果/无业务符号）。
- 关键证据列：**cap_8 的 com/acse 全树 0 处 `System.loadLibrary`**（全 cap_8 仅 8 个文件有，且都在 com/google/cn 等第三方），→ 7 个 Activity 的 native 无静态可证的解析库归属。
- tsnsecret 标注为**已映射**（unidbg 已验证），不是"待排除第三方"。

### 4.4 URL 复核+增量（第 6 条）
- 与 `体适能_脱壳取证_acse.ottn.md` §2（URL 表，报告第 238-247 行等）**去重复核**，不是重做。
