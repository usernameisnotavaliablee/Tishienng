### 2.1 Home 键 / 熄屏监听

**两套实现并存，但只有一套真正接线**：

**① `HomeKeyReceiver.java`（manifest 声明，但无 intent-filter、无 Java registerReceiver）**：
- `onReceive`（`:125-148`）：处理 `android.intent.action.CLOSE_SYSTEM_DIALOGS`，`reason=="homekey"`→`a(context)`；`reason=="recentapps"`→空操作。
- `a(context)`（`:69-117`）：按当前时刻 `HHmm` 落在 `[800,1400)` 或 `[1400,2100)` 分上下午，且与 `am_show_seed_dialog`/`pm_show_seed_dialog` 记录不同才触发 `a(ctx, key, time)`。
- 但 `a(ctx, key, time)`（3 参，`:119-122`）**是空实现**（直接 return）。
- manifest `1255-1256`：`<receiver name="com.acse.ottn.receiver.HomeKeyReceiver">` **无 `<intent-filter>`**，且全 acse 源码无 `registerReceiver(HomeKeyReceiver)`。

→ **HomeKeyReceiver 在 Java 层是"半成品/空壳"**：声明了、逻辑写了，但既没静态 intent-filter 也没动态注册，导流弹窗动作还是空的。**强推断**：Home 键导流逻辑被抽空/废弃，或走 native/壳侧注册（需运行时验证）。

**② `m1.java`（真正生效的动态注册监听，实锤）**：

  - `m1$a` 监听 `CLOSE_SYSTEM_DIALOGS`（`:411-416`）→ 收到后 `finishAndRemoveTask()` 关闭自家广告 Activity（`:75-77`）。
  - `m1$b` 监听 `SCREEN_OFF`（`:417-422`）→ `finishAndRemoveTask()`（`:122-124`）。
- `a(activity, bool)`（`:372-401`）判断当前 Activity 是否为 `ExcessActivity`/`SeedingLoadingActivity`/`WhiteActivity`（只对自家导流页生效）。
- 日志：`"收到注册广播"`、`"结束当前activity1"`、`"结束当前activity2"`。

### 2.8 多进程

- acse SDK 的 **Service/Activity 统一声明 `process=".LoadingActivity"`**（`manifest_decoded.xml:697/1225/1227/1229/1237/1245/1253/1261-1280`）——SDK 运行在**独立于宿主主进程的专属进程**（进程名以 `.LoadingActivity` 结尾，是宿主包名下的独立进程；区别于极光 `:pushcore`、模拟器检测 `:EmulatorCheckService` 的 `:` 前缀写法）。
- 效果：**SDK 与宿主隔离**，宿主主进程被系统杀/崩溃不影响 SDK 进程的悬浮窗与无障碍服务存活；反之 SDK 也不拖累宿主。这是典型的"独立进程寄生"设计。
- 跨进程拉起：未见 `bindService`/`startService` 显式跨进程调用（同一 `.LoadingActivity` 进程内互相 startService）；跨进程联动主要靠**广播（CLOSE_SYSTEM_DIALOGS/SCREEN_OFF）**与**无障碍系统服务回调**。

### 2.9 自启 / 复活链路拼图

**事实澄清（重要）**：`深挖补充证据.md §1.3` 曾把 `BOOT_COMPLETED`、`ACTION_POWER_CONNECTED/DISCONNECTED`、`BATTERY_LOW/OKAY`、`TIME_SET`、`TIMEZONE_CHANGED`、`DEVICE_STORAGE_LOW/OK`、`CONNECTIVITY_CHANGE` 归给"com.acse.ottn 的 HomeKeyReceiver"。经核对 `manifest_decoded.xml:1169-1210`，**这些 action 全部属于 `androidx.work.impl.background.systemalarm.ConstraintProxy*` 与 `RescheduleReceiver`（AndroidX WorkManager 组件）**，与 acse 无关：

```xml
<receiver name="androidx.work.impl.background.systemalarm.ConstraintProxy$BatteryChargingProxy" ...>
  <intent-filter><action ...ACTION_POWER_CONNECTED/>...DISCONNECTED/></intent-filter>   <!-- :1171-1178 -->
<receiver ...ConstraintProxy$BatteryNotLowProxy> BATTERY_OKAY/BATTERY_LOW              <!-- :1179-1186 -->
<receiver ...ConstraintProxy$StorageNotLowProxy> DEVICE_STORAGE_LOW/OK                 <!-- :1187-1194 -->
<receiver ...ConstraintProxy$NetworkStateProxy> CONNECTIVITY_CHANGE                    <!-- :1195-1200 -->
<receiver ...RescheduleReceiver> BOOT_COMPLETED/TIME_SET/TIMEZONE_CHANGED             <!-- :1201-1210 -->
```

而 acse 的 `HomeKeyReceiver`（`manifest_decoded.xml:1255-1256`）**没有任何 `<intent-filter>`**。

**acse 侧自启/复活完整链路拼图（按证据强度）**：

1. **无障碍服务自持**（实锤）：`ShopHelperService` 是系统级无障碍服务，用户一旦开启，系统会维持它运行；`onServiceConnected`（`ShopHelperService.java:316-336`）即自启 SDK。
2. **动态广播监听**（实锤）：`m1.java` 动态注册 `CLOSE_SYSTEM_DIALOGS` + `SCREEN_OFF`（`:411-422`）。
3. **独立进程 `.LoadingActivity`**（实锤）：SDK 与宿主隔离，宿主被杀不影响 SDK。
4. **心跳定时器**（实锤）：`d.h()` 每天一次 `Timer` 心跳（`:5369-5399`）。
5. **电池白名单/自启动诱导**（实锤）：`b5.java` + Green Activity 逐项诱导（提高后台存活率）。
6. **设备管理员 `force-lock` + ScreenLock 层 + 锁屏触发**（实锤策略声明，触发点强推断）：`res/cq.xml`、`b4.java`、`l2.java:45-51`。
7. **"复活"（被系统杀死后拉起）本身：未发现**。`StartProcreeService` 空壳；无 `AlarmManager`/`JobScheduler`/`WorkManager`/`BOOT_COMPLETED`（acse 侧）；无 `startForeground`。**即"被系统杀死后自动复活"的硬机制在 acse 反编译 Java 层不成立**，主要靠"无障碍服务系统级自持 + 用户被诱导开满权限 + 服务器任务拉活"维持。

## 三、事实 / 强推断 / 未发现 三档总结

### 实锤（代码直接坐实）

1. 无障碍服务监听**全部事件类型**（`res/uk.xml` eventTypes=0xffffffff），实时读窗口、模拟手势、截屏、注入网页（`深挖补充证据.md §3`）。
2. `ShopHelperService` 把窗口/点击事件分发到 `d` 引擎；无障碍一开启即自启 SDK（`ShopHelperService.java:259-265/316-336`）。
3. 硬编码 **40+ 电商/外卖/视频/出行 App 的具体 Activity 类名**做精准页面识别（`o.java:332-443` + `d.java` 全表）。
4. 自动点击 **"立即领取"等 15 个默认关键词**、**点京东商品标题**、**抢微信红包**（`d.java:4912-4941/4810-4886`、`b.java:1189-1354`）。
5. 坐标点击/滑动（`dispatchGesture`）、文本输入（`ACTION_SET_TEXT`）、长按、滚动、模拟 Home/返回（`b.java:574-637/640-652/835-846`）。
6. **截屏**：`takeScreenshot` → 裁剪 → JPEG(20) → Base64 存 `d.m/d.n` 供上报（`a3.java:142-246/600-636`）。
7. 触发源双轨：本地 `Timer.scheduleAtFixedRate` 心跳（每天一次，上报 `heart_beat`+枚举竞品无障碍服务）+ 服务器 `AccessiblityModel` 任务模型（`d.java:5369-5399`、`n0.java:309-328`、`AccessiblityModel.java`）。
8. Green Activity 成体系诱导：无障碍/悬浮窗/定位/电池/自启动五项清单，逐项弹窗并回传 allow/refuse 埋点（`AccessibiltyTsnPermissionGreenActivity.java`、`TransparentGreenActivity.java:272-347`）。
9. 10 个 `exported=true` Service + 8 套 `TYPE_APPLICATION_OVERLAY/TYPE_PHONE/TYPE_ACCESSIBILITY_OVERLAY` 悬浮窗（`manifest_decoded.xml:1261-1280`、`m2/i0/o0/e2/ExcessService/WebViewService/TransparentService/b4`）。
10. 设备管理员策略声明 **`force-lock`** + `l2.java` 检测 `isAdminActive` + ScreenLock 悬浮层（`res/cq.xml`、`l2.java:69-122`、`b4.java`）。
11. 电池优化豁免 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`（三星分支）+ 分厂商自启动跳转 + `AppOpsManager` 反射检测悬浮窗权限（`b5.java:130-232`）。
12. Home/熄屏时 `finishAndRemoveTask()` 抹掉自家导流 Activity（`m1.java:75-77/122-124`）。

### 强推断（代码+上下文高度指向，非代码直接写死）

1. **锁屏触发**：`l2.java:45-51` 的 `performGlobalAction(8)=GLOBAL_ACTION_LOCK_SCREEN`（SDK≥28）是锁屏动作，效果等同 lockNow；但 `what==1` 的发送方在 Java 层不可见 → 推断由 native/反射触发。
2. **`StartProcreeService`（"进程复活 Procree"）为空的真实复活逻辑**可能在 native 侧或被抽空；Java 层仅剩打日志。
3. **截图上报**：`a3` 截图 base64 存 `d.m`（字段注释 "imageBase64"）→ 与 `api/sys_pic` 接口对应，推断截屏内容最终上传服务器。
4. **无障碍授权对话框自动定位**：`d.java:5409-5433` 遍历 `getWindows()` 找标题"点按相应功能即可开始使用："的窗口，指向"自动帮用户定位无障碍开关页/授权弹窗"。
5. **HomeKeyReceiver 导流弹窗**：逻辑残留在 `HomeKeyReceiver.java:69-117`，但触发动作空实现且无注册 → 推断为废弃/半成品或壳侧接线。
6. **独立进程 `.LoadingActivity`**：SDK 与宿主隔离，宿主被杀不拖累 SDK 悬浮窗/无障碍存活。

### 未发现（全包 grep 无命中）

1. `startForeground`（无前台服务化）。
2. `DevicePolicyManager.lockNow()`（但存在 `performGlobalAction(LOCK_SCREEN=8)` 等价点，见强推断 1）。
3. `AlarmManager` / `setExact` / `setRepeating`。
4. `JobScheduler` / `JobInfo` / `WorkManager` / `PeriodicWork`。
5. **acse 侧 `BOOT_COMPLETED`/`RECEIVE_BOOT_COMPLETED` 注册**（manifest 里的 BOOT/电量/时区 action 属 androidx.work，非 acse）。
6. `HomeKeyReceiver` 的静态 intent-filter 或动态 `registerReceiver`（→ 该 receiver 实际未在 Java 层接线）。
7. SDK 自己的常驻通知（`p4.java` 的 notify 属极光推送通道）。
8. 显式跨进程 `bindService` 拉起。
